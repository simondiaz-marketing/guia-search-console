01 · Lo esencial

Antes de empezar

Esta guía acompaña a quienes crearon su primera web, con inteligencia artificial o sin ella. El ejemplo utiliza una página estática con HTML, CSS y JavaScript, GitHub y Netlify. Si tu web ya está publicada, podés empezar por Search Console.

Una aclaración importante: publicar, rastrear, indexar y posicionar son cosas distintas. Google no garantiza la indexación, una fecha ni una posición.

Publicación

Tu página queda disponible en Internet mediante un servicio de alojamiento.

Rastreo

Google puede descubrir la URL y enviar Googlebot para visitar su contenido.

Indexación

Google analiza la página y decide si la incorpora a su índice.

Posicionamiento

Google determina qué resultados mostrar y en qué orden para cada búsqueda.

Search Console es una herramienta gratuita para inspeccionar URLs, revisar posibles problemas y consultar rendimiento. No publica tu web ni obliga a Google a indexarla.

En el video se usa una web de demostración ↗, que podría dejar de estar disponible. Usá siempre tu propio sitio y tu propio repositorio para seguir los pasos.

03 · Preparación

Prepará tu proyecto

Para recorrer el ejemplo necesitás una web o sus archivos, una cuenta de Google, acceso al código y al despliegue. Si vas a publicar con GitHub y Netlify, necesitás cuentas en ambos, además de VS Code y Git instalados.

mi-sitio/
├── index.html    # estructura y contenido
├── styles.css    # diseño visual
├── script.js     # interacciones
├── sitemap.xml   # opcional: páginas importantes
└── robots.txt    # opcional: reglas de rastreo

Esta es solo una estructura de ejemplo. En proyectos con frameworks o compilación los archivos pueden estar en otras carpetas o generarse automáticamente.

Seguridad: no subas contraseñas, claves API ni archivos .env al repositorio. Revisá las propuestas de un agente de IA antes de autorizar cambios o publicaciones.

Git y GitHub no son lo mismo

Git registra versiones del proyecto. GitHub aloja un repositorio y su historial en Internet. Un commit registra cambios, una rama organiza una línea de trabajo y un push envía cambios al repositorio remoto.

04 · Publicación

Publicá tu sitio en Netlify

Si ya está en línea, pasá al siguiente bloque. Este recorrido usa GitHub, aunque hay otras formas de publicar.

1. Abrí el proyecto

  1. Instalá VS Code y Git. Abrí la carpeta de tu web desde el editor.
  2. Comprobá que tu página principal exista. En una web estática sencilla suele ser index.html.
  3. En Control de código fuente, inicializá un repositorio si todavía no existe. Revisá los archivos y creá un commit.
  4. Publicá el proyecto en tu cuenta de GitHub o conectalo con un repositorio propio. Elegí su privacidad y no incluyas secretos.

2. Conectá GitHub a Netlify

  1. En Netlify, buscá la opción de importar un nuevo proyecto desde Git y conectá GitHub.
  2. Seleccioná tu repositorio y revisá la configuración. El directorio de publicación debe apuntar a la carpeta que contiene los archivos públicos; depende de tu proyecto.
  3. Iniciá el despliegue y esperá a que se publique. Abrí y guardá la URL principal.

3. Elegí la URL correcta

Producción

Dirección pública estable que vas a compartir y registrar en Search Console.

Preview

Dirección temporal para revisar un cambio. No la confundas con producción.

Abrí la URL de producción en una ventana privada. Si querés que Google acceda, la página debe cargar públicamente sin contraseña. Los cambios enviados a la rama de producción configurada pueden activar un nuevo despliegue.

05 · Search Console

Agregá tu web como propiedad

Una propiedad es el sitio, parte de un sitio o cuenta de plataforma sobre el que consultás información.

SITIO WEB

Dominio

Abarca el dominio definido, sus subdominios y protocolos. Generalmente se verifica mediante un registro DNS; necesitás acceso a esa configuración.

SITIO WEB

Prefijo de URL

Abarca las direcciones que comienzan con el prefijo exacto, incluido el protocolo. Admite varios métodos de verificación, como una etiqueta HTML.

Para una dirección .netlify.app, normalmente no administrás el DNS de Netlify. En este ejemplo usaremos Prefijo de URL. Con un dominio propio y acceso al DNS, podés evaluar la propiedad de dominio.

  1. Entrá a Google Search Console con tu cuenta.
  2. Abrí el selector de propiedades y elegí Añadir propiedad.
  3. Elegí Prefijo de URL e introducí tu dirección completa, con https:// y barra final.
  4. Continuá hasta las opciones de verificación.
https://mi-sitio.netlify.app/

El ejemplo es ficticio: reemplazalo por tu URL pública real. Los prefijos con HTTP, HTTPS o subdominios distintos no son equivalentes. Tipos de propiedad ↗

06 · Verificación

Demostrá que controlás tu web

Vamos a usar la etiqueta HTML que Search Console genera para tu cuenta. En una web estática simple, se agrega al <head> de la página principal.

  1. En Search Console elegí Etiqueta HTML y copiá la etiqueta completa.
  2. Abrí index.html en VS Code y pegala dentro del <head> sin borrar otros metadatos. En un framework, buscá su método para gestionar metadatos.
  3. Guardá el archivo, revisá el cambio y subilo a la rama de producción configurada en GitHub.
  4. Esperá a que Netlify termine el despliegue. Abrí la URL pública y seleccioná Ver código fuente; buscá google-site-verification.
  5. Volvé a Search Console y pulsá Verificar.
<head>
  <meta charset="UTF-8">
  <meta name="google-site-verification" content="TU_CODIGO">
  <title>Mi sitio web</title>
</head>

Usá tu etiqueta real: TU_CODIGO es solo un ejemplo. Conservá la etiqueta después de verificar; Google puede volver a comprobarla. Si falla, revisá el despliegue, la URL final si hay redirección y el HTML público.

07 · Descubrimiento

Un mapa para tus páginas

sitemap.xml enumera direcciones importantes de tu sitio para ayudar a los buscadores a descubrirlas. Para una web pequeña y bien enlazada puede no ser necesario, y enviarlo no garantiza indexación.

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://mi-sitio.netlify.app/</loc>
  </url>
</urlset>

urlset agrupa las direcciones, cada url representa una página y loc contiene su URL pública completa. Reemplazá la URL ficticia por la tuya y agregá bloques para otras páginas relevantes.

Incluí páginas públicas y canónicas; evitá contenido privado, pruebas, previews y duplicados. La fecha lastmod es opcional y, si se usa, debe representar una modificación significativa real.

Publicar y enviar

  1. En una web estática simple, guardá el archivo en el directorio que se publica para que sea accesible desde la raíz. Con un framework, seguí su convención.
  2. Publicá los cambios y abrí https://tu-sitio.netlify.app/sitemap.xml; comprobá que muestra XML, no un error o la página de inicio.
  3. En la propiedad verificada de Search Console, abrí Sitemaps, escribí sitemap.xml en el campo correspondiente y pulsá Enviar.
  4. Consultá el estado. Un sitemap procesado no implica que todas sus páginas estén indexadas.

08 · Rastreo

Instrucciones para robots

robots.txt comunica reglas de rastreo y se publica en la raíz del sitio, por ejemplo https://tu-sitio.netlify.app/robots.txt. No es obligatorio para que Google indexe tu web.

# Reglas para todos los rastreadores
User-agent: *

# Permitir el rastreo del sitio
Allow: /

# Ubicación del sitemap, si existe
Sitemap: https://mi-sitio.netlify.app/sitemap.xml

User-agent: * identifica rastreadores en general; Allow: / permite rastrear desde la raíz y Sitemap: señala el mapa publicado. No hace falta crear este archivo solo para permitir todo; omití la línea Sitemap si no tenés uno.

Una regla como Disallow: /borradores/ pide no rastrear las rutas que empiezan por esa dirección. Es solo un ejemplo. Disallow: / bloquea el rastreo de todo el sitio para los rastreadores afectados: evitá copiarlo accidentalmente.

No es una cerradura. Robots.txt no protege información privada ni garantiza que una URL desaparezca de Google. Para privacidad usá control de acceso. La directiva noindex va en el HTML o una cabecera; Google necesita poder rastrear la página para leerla.

No bloquees recursos CSS o JavaScript que Google necesite para interpretar la página. Guía oficial de robots.txt ↗ · Aprendé sobre noindex ↗

09 · Seguimiento

Inspeccioná y solicitá indexación

  1. En tu propiedad verificada, pegá la URL completa de la página principal en la barra superior de Inspección de URL.
  2. Revisá el estado. Si es una web nueva, puede que aún no esté en Google.
  3. Pulsá Probar URL publicada para examinar la versión actual y detectar posibles bloqueos.
  4. Si corresponde, pulsá Solicitar indexación.

La prueba en vivo y el estado de indexación son diferentes: que la web sea accesible ahora no significa que ya esté indexada. La solicitud no garantiza una fecha ni una posición; no hace falta repetirla todos los días.

¿Cuánto tarda?

No hay un plazo universal. En el video se cuenta una experiencia personal de varios días, no un tiempo que deba cumplirse para todos los sitios. Una búsqueda normal sin resultados tampoco demuestra por sí sola que una URL no esté indexada: consultá su estado con la inspección.

Volvé periódicamente a Search Console para revisar Indexación de páginas, el estado de Sitemaps y las impresiones y clics en Rendimiento cuando existan datos.

10 · Para creadores

Tu contenido en redes sociales

Search Console también permite propiedades de plataforma para cuentas o canales compatibles, como Instagram, YouTube, TikTok y X. Permiten consultar cómo se encuentra ese contenido en Google; no son una propiedad de dominio o de prefijo de tu web.

  1. Abrí el selector de propiedades y elegí Añadir propiedad.
  2. Buscá la plataforma disponible que querés conectar.
  3. Seguí las indicaciones de conexión y verificación de Google.
  4. Repetí el proceso por cada cuenta o canal que quieras consultar.

Los datos pueden tardar unos días. Estos informes complementan, pero no reemplazan, las estadísticas de cada plataforma. Conectar una cuenta no garantiza que sus publicaciones se indexen ni su posición.

11 · Asistencia con IA

Pedí ayuda, conservá el control

Usá una herramienta de confianza y revisá su propuesta antes de editar o publicar. No compartas contraseñas, claves API, archivos .env ni información privada.

1. Localizar la etiqueta de verificación

Quiero verificar mi sitio en Google Search Console.

Analizá este proyecto y explicame qué tecnología utiliza, qué archivo o componente genera el <head> de la página principal y dónde debería colocar la etiqueta de verificación.

Mostrame el cambio mínimo propuesto y explicalo en lenguaje simple. No modifiques ni publiques ningún archivo hasta que lo revise y te dé mi aprobación.

Etiqueta:
[PEGAR AQUÍ LA ETIQUETA DE GOOGLE]

2. Crear un sitemap

Analizá este proyecto y ayudame a preparar un sitemap.

Mi URL de producción es: [PEGAR URL DE PRODUCCIÓN]

Identificá las páginas públicas que deberían incluirse. Excluí rutas privadas, páginas de prueba, previews y duplicados. Mostrame primero la lista de URLs propuesta y explicame dónde debería guardarse el sitemap para que se publique correctamente.

No crees ni modifiques archivos hasta que confirme la lista.

3. Revisar problemas de indexación

Revisá este proyecto para detectar posibles problemas de rastreo o indexación: etiquetas noindex, reglas de robots.txt, redirecciones, páginas protegidas, problemas en el sitemap y diferencias entre producción y previews.

Separá los problemas que podés confirmar en el código de los que necesitan comprobarse en la web publicada. No modifiques ni publiques nada hasta que apruebe los cambios.
12 · Diagnóstico

Cuando algo no funciona

La etiqueta no aparece

Comprobá la URL de producción, el despliegue, el código fuente público, el contenido de la etiqueta y la página final si hay redirecciones.

No se puede leer el sitemap

Verificá que abra como XML en su URL pública, que esté publicado, que sus URLs sean completas y que hayas elegido la propiedad correcta.

La web no aparece

Inspeccioná la URL, revisá acceso, noindex, redirecciones y reglas de rastreo. Leé el motivo de Search Console antes de modificar archivos.

La cuenta no muestra datos

Confirmá la cuenta o canal y su verificación. Los informes pueden tardar unos días en mostrar información.
